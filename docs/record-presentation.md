# 档案展示与字段编辑模型

本文档规定星原 SIS 记录型工作台的**展示值管线**。它补充 `design-principles.md` 与 `ui-design.md`：已有记录可以在原档案中直接修改字段，但“正在修改”绝不能形成第二套展示语义。

## 1. 核心不变量

同一个字段只有一种格式化规则。

浏览、文本输入、枚举选择、外键选择都必须经过同一条管线：

```text
数据库当前记录
      │
      ├─ 无字段修改 ───────────────┐
      │                           │
      └─ 当前字段临时值 ── overlay │
                                  ▼
                         projected record
                                  │
                                  ▼
                         display_value(...)
                                  │
                                  ▼
                           inspector layout
```

`projected record` 是渲染器唯一消费的数据形状。它等于已提交记录，加上**当前字段会话明确拥有的临时值**。格式化函数不知道这些值来自数据库还是临时输入。

因此禁止出现：

```text
if editing:
    用编辑态格式化
else:
    用展示态格式化
```

也禁止通过 `form.mode`、`Workspace`、焦点状态等信息决定字段应该显示成什么文字。

## 2. 状态职责

### 已提交记录

数据库 / `Catalog` 快照是记录事实来源。没有正在修改的字段时，档案直接投影该记录。

### 字段会话

已有记录的字段修改只拥有：

- 当前字段键；
- 当前临时值；
- 必要时的选项列表与选中位置；
- 原子复合字段明确列出的同组字段，例如学生 `family + branch`。

字段会话可以改变焦点、展开选项、决定 Enter / Esc 的含义，但**不能改变其他字段的值来源或格式化方式**。

### 完整 Form

新建记录、导入、导出、删除确认、seed 等完整事务仍可使用 `Form`。这些操作不是已有记录的字段展示状态，不参与档案字段格式化。

## 3. 唯一格式化路径

`tui/workspace/presentation.py` 提供两个共享步骤：

```text
project_record(row, form)
display_value(catalog, collection, values, field_key)
```

`project_record` 只做数据投影：复制当前记录，并覆盖当前字段会话拥有的键。

`display_value` 只做字段显示：

1. 取得字段当前值；
2. 若字段存在枚举 / 外键选项，用同一套 option label 映射；
3. 否则使用通用安全文本格式；
4. 不读取 `Workspace`、`Form.mode`、焦点或页面状态。

学生专用 inspector 与其他实体通用 inspector 都必须调用这套路径，不得各自增加第二套 `_shown_value(editing=...)` 或类似逻辑。

## 4. 派生信息

未被当前字段会话拥有的派生信息继续基于已提交记录。

例如修改学生“入学年份”时：

- 入学年份可以显示当前临时输入；
- 班级仍按已提交 `class_code` 用正常班级 label 展示；
- 学院仍显示已提交班级关系对应的学院；
- 学籍、元素、选课、个人信息完全不变。

只有保存成功、`Catalog.refresh()` 取得新记录后，其他派生信息才随真实数据变化。

复合字段是唯一允许一次投影多个临时键的情况。例如修改物种时，`family + branch` 属于同一个原子操作，因此这两个键可以共同进入 projected record；其他字段仍不得参与。

## 5. 交互与展示必须分离

下列行为可以因字段会话存在而变化，因为它们属于交互层：

- 当前 target 的选中样式；
- 选项列表是否展开；
- Enter 是打开字段还是确认值；
- Esc 是返回档案还是取消当前字段；
- 输入期间是否暂时锁定其他 target。

下列行为不得因字段会话存在而变化，因为它们属于展示层：

- 相同值的文本格式；
- 外键 / 枚举 label 规则；
- 未编辑字段的显示值；
- 区块结构与字段顺序；
- 与当前字段无关的派生信息。

## 6. 回归要求

修改档案或字段编辑时至少应满足：

1. 同一个记录在进入字段会话前后，除当前字段允许的临时值与局部交互控件外，其他可见文本一致；
2. 外键字段在浏览和修改时使用同一个 label，例如班级始终显示同一套“名称 · 编号”格式；
3. 格式化 helper 的参数中不出现 `editing`、`mode` 或整个 `Workspace`；
4. 新增字段类型时，只扩展统一格式化 / options 规则，不增加“编辑态版本”；
5. 若修复某字段导致其他字段展示变化，应先检查投影边界，而不是增加新的条件分支。

这套约束的目标不是“让两套页面看起来一样”，而是从模型上保证**根本不存在两套字段展示逻辑**。
