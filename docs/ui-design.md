# Terminal UI 设计规范

本文档规定星原 SIS 当前 TUI 的视觉与交互语义。它描述**现在应该成立的设计**，不记录已经淘汰的实现路径。结构性约束见 [设计原则](design-principles.md)，模块职责见 [架构文档](architecture.md)。

## 1. 设计目标

终端界面首先要让用户形成稳定的空间与操作模型，而不是追求控件数量或装饰效果。

核心目标：

1. 同一时刻只有一个明确的键盘焦点；
2. “当前位置”“当前记录”“当前焦点”使用不同但一致的视觉语义；
3. 宽窄终端可以重新排布，但操作含义不变；
4. 同一概念只有一个 renderer / 状态模型；
5. 颜色只表达语义角色，不成为页面局部约定；
6. 文本输入期间，普通字符永远属于文本，不被全局快捷键截获。

## 2. 唯一首页模型

登录后的 TUI 只有一条首页路径：

```text
app.run → app._portal_home → portal.frame
```

`portal.py` 同时定义管理员和学生看到的一级 / 二级导航。不得增加另一套“旧首页”“简化首页”或仅供测试使用的 home renderer。

一级导航固定为：

```text
首页
教务
个人中心
退出登录
```

身份差异通过二级菜单表达：管理员拥有管理实体，学生只获得允许的查询与个人操作。权限差异不通过复制整套导航实现。

## 3. 焦点模型

必须区分三个概念：

- **当前位置（current location）**：用户属于哪个页面或一级栏目；
- **当前记录（current record）**：名册中哪条记录提供右侧上下文；
- **键盘焦点（focus）**：方向键 / Enter 此刻作用在哪个控件或面板。

它们不能全部使用同一种高亮，否则用户会同时看到多个“当前”。

### 一级 / 二级导航

一级项拥有焦点时：

- 当前项使用 `text-accent + bold`；
- 使用 `▌` 表示一级焦点；
- 二级菜单只是预览，不显示第二个焦点。

进入二级菜单后：

- 一级项降为当前位置提示，使用 `▏`；
- 二级当前项使用 `surface-selected + text-on-selected`；
- 不再叠加 `>`、`›` 等额外箭头。

焦点只能有一个，不靠“再多加一个标记”解决不清楚的问题。

## 4. 工作台模型

学生、学院、专业、班级、课程、成绩和数据页共享同一工作台框架。记录型页面的核心结构是：

```text
页面标题 / 搜索与视图

名册                     档案
当前记录                 当前记录的内容与操作

底栏
```

宽屏时名册与档案并列；窄屏时可以单面板展开，但二者仍属于同一个状态机。

### 面板焦点

- `Tab` 在名册与档案之间切换；
- `→` 定向进入右侧档案；
- `←` 定向回到左侧名册；
- 已经位于目标面板时重复按方向键必须幂等，不反向切换；
- 获得焦点的面板标题使用 `▌`；
- 左侧当前记录即使失去焦点也保留弱选中态，继续提供右侧上下文。

因此“记录被选中”和“记录列表获得焦点”是两种状态：

- 聚焦名册：`surface-selected + text-on-selected`；
- 焦点在右侧时：当前记录使用 `surface-interactive + text-primary`。

## 5. 学生档案

学生档案由 `tui/workspace/student_inspector.py` 唯一负责。通用 `detail.py` 不维护第二份学生结构。

信息层级固定为：

```text
姓名
学号
物种      族系 · 支系
性别
年龄
入学
学院
班级
学籍
元素      主元素 · 亲和

选课与成绩
  …

个人信息
出生日期
联系方式
宿舍
备注
```

设计约束：

- 性别和年龄各占一行，不因为节省空间合并；
- 族系 + 支系属于同一个“物种”概念，合并显示；
- 主元素 + 亲和属于同一个“元素”概念，合并显示；
- 性别不在“个人信息”中重复；
- 年龄由出生日期即时派生，不是独立数据库字段；
- 浏览与编辑共享同一档案几何，编辑不能切换成第二套“表单页面”；
- 选课记录、可编辑字段等右侧动作属于同一个选择序列。

如果将来学生档案发生变化，应修改这一份结构及其测试，而不是在通用档案中增加另一份学生分支。

## 6. 其他实体档案

学院、专业、班级、课程、成绩使用通用档案模型：

```text
识别信息
关联记录
详细属性
```

通用组件只表达真正共有的行为。某实体只有在交互模型确实不同、无法由现有模型自然表达时，才允许建立专用 inspector。

“只是想换几行排版”不构成复制 renderer 的理由。

## 7. 语义颜色

颜色值只在 `src/xingyuan_sis/tui/tokens.py` 定义。绘制层使用同名语义 token，不存在第二套历史别名。

### 文本角色

| Token | 含义 | 典型内容 |
| --- | --- | --- |
| `text-primary` | 主要信息 | 正文、值、区块标题 |
| `text-secondary` | 次级信息 | 标签、说明、位置提示 |
| `text-accent` | 当前 / 重点 | 页面标题、当前导航、焦点 |
| `text-on-selected` | 选中表面上的文字 | 选中行、选中按钮 |
| `text-danger` | 错误 / 不可逆风险 | 删除、失败状态 |

### 表面与结构

| Token | 含义 |
| --- | --- |
| `surface-default` | 页面背景 |
| `surface-topbar` | 顶栏 |
| `surface-footer` | 底栏 |
| `surface-interactive` | 有上下文但未聚焦的交互表面 |
| `surface-selected` | 当前键盘选择 |
| `border-subtle` | 弱结构边界 |

`decorative-gold` 只用于装饰，例如首页轨道，不能承担成功、警告、焦点等信息语义。

组件需要组合状态时直接组合语义角色，例如：

```text
surface-selected + text-on-selected
surface-interactive + text-primary
surface-topbar + text-secondary
```

这种组合属于组件样式，不再注册 `_SELECTED`、`_SURFACE` 等第二套全局名称。

## 8. 信息层级

视觉优先级从高到低：

1. 当前页面 / 当前焦点：`text-accent`，必要时加粗；
2. 区块标题：`text-primary + bold`；
3. 关键值：`text-primary`，少量真正需要扫读的值可强调；
4. 普通正文：`text-primary`；
5. 标签、说明、辅助状态：`text-secondary`；
6. 分隔线：`border-subtle`。

禁止因为“看起来统一”就把标题、标签和值都染成强调色。统一来自语义一致，不来自颜色一致。

## 9. 顶栏与底栏

### 顶栏

全站使用 `theme.topbar`：

- 左侧固定应用身份 `✦ 星原 SIS`；
- 右侧放账号 / 身份 / 本地数据库等次级上下文；
- 空间不足时优先保留应用身份，次级信息可以裁减。

### 底栏

门户底栏是稳定导航契约：

```text
[ 方向键 移动 ]   [ Enter 打开 ]   [ Esc 返回 ]
```

底栏不因“首页 / 教务 / 退出登录”而频繁改写词义。具体页面可在正文中给出额外动作，但全局底栏保持稳定。

工作台可以显示与当前工作区相关的快捷键提示，但 `Esc` 始终承担“退出当前最内层状态”的统一语义。

## 10. 返回与取消

`Esc` 是 UI 对用户展示的默认返回 / 取消键：

- 浏览页面：返回上一层；
- 右侧焦点 / action focus：先退出当前焦点层；
- 表单 / 选择器：取消当前编辑层；
- 文本输入：取消本次输入并恢复原状态；
- 首页：退出 TUI。

终端层可以继续接受 `q`、`0`、`Ctrl+C` 等习惯输入，但它们只是输入协议便利，不构成第二套导航模型，UI 也不需要把多个等价退出键堆在提示里。

## 11. 文本输入

`TextBuffer` 是文本编辑的唯一状态模型，拥有：

- 字符序列；
- 光标位置；
- 插入 / 删除 / 左右移动；
- 给定显示宽度下的可见窗口；
- secret 模式的掩码显示。

`terminal_input.py` 和认证页面直接使用 `TextBuffer`。不得再建立 `chars + cursor → 临时 TextBuffer` 的 wrapper；否则同一个编辑状态会出现两种表示。

进入文本输入后：

- 普通字母、`/`、`q` 等全部属于文本；
- Tab 的意义由当前输入控件定义；
- Esc 取消；
- 中文、组合字符和宽字符必须按终端 cell 宽度处理，而不是按 Python 字符数处理。

## 12. 响应式约束

响应式不是维护“桌面版 UI”和“手机版 UI”两套界面，而是同一状态模型的几何变化。

必须保证：

- 所有可见按钮的 hit region 与实际字符位置一致；
- 当前选中项在尺寸变化后仍可见；
- 窄屏可以隐藏预览，但不能让进入后的菜单项不可达；
- 裁剪按 terminal cell 处理，不切断 ANSI 序列或双宽字符；
- 滚动只在选择越过可见边缘时推进 viewport；
- 首页动画不得覆盖正文、交互区域或底栏。

`WorkspaceLayout` 和 `visible_start` 是工作台几何 / viewport 的权威实现，渲染与事件不得各自复制断点算法。

## 13. 动画

首页星球与星光是装饰层：

- 动画不能改变导航语义；
- 可点击区域和正文单元格属于保护区；
- 星光只写入可用空白 cell；
- 暂停 / 恢复应保持原相位，不重置场景；
- `NO_COLOR` 关闭颜色时，结构和焦点仍必须可理解。

动画代码不能成为第二套页面 renderer。

## 14. 测试要求

UI 回归测试应验证用户可观察的契约：

- portal 在各种尺寸下所有目标可见且可点击；
- 名册 / 档案焦点与当前记录语义不同；
- 学生 inspector 只有一份信息层级；
- 编辑不跳出当前档案结构；
- 文本输入使用同一个 `TextBuffer`；
- 终端退出后恢复 cursor / alternate screen；
- `NO_COLOR` 不破坏操作结构；
- 动画不覆盖正文和 hit region。

测试不得为了保留已经退出生产路径的私有 renderer、别名 token 或 wrapper 而阻止删除旧代码。

## 15. 修改检查

每次 UI 修改至少检查：

1. 是否制造了第二个焦点？
2. 是否为同一概念增加了第二个 renderer / 状态模型？
3. 是否新增了局部 ANSI 色号而没有语义 token？
4. 是否让宽屏 / 窄屏拥有不同业务行为？
5. 是否让测试依赖私有历史接口而不是当前行为？
6. 是否有一次性页面需求被升级成全局 UI 规则？

任何一项为“是”，都应先重新审视设计再合并。
