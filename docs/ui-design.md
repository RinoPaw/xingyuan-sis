# Terminal UI 设计规范

本文档规定星原 SIS 当前 TUI 的视觉与交互语义，只描述现在成立的设计。

## 1. 设计目标

1. 同一时刻只有一个明确键盘焦点；
2. “当前位置”“当前记录”“当前焦点”使用不同语义；
3. 宽窄终端可以重新排布，但操作含义不变；
4. 一个字段只有一个稳定身份和一套展示规则；
5. 文本输入期间普通字符不被全局快捷键截获；
6. 鼠标与键盘表达同一个意图时进入同一处理路径；
7. 用户看到的最终屏幕几何就是方向键使用的几何；
8. 物理按键、命令和业务动作各自只有一个职责。

## 2. 门户与工作台

登录后的 TUI 由 `app.py + portal.py` 唯一负责。管理员和学生共享门户结构，只按权限显示不同入口。

记录型页面共享：

```text
工具栏 / 视图

名册                     档案
当前记录                 字段与关联

状态栏
底栏
```

宽屏名册与档案并列；窄屏单面板展开，但仍属于同一个 `Workspace`。

## 3. 焦点模型

必须区分：当前位置、当前记录、键盘焦点和窄屏当前内容面板。

`Workspace.focus` 是唯一键盘焦点：

```text
ROSTER      名册 / 列表
INSPECTOR   档案
TOOLBAR     操作栏
DASHBOARD   数据页主体
```

记录型页面只有一个 Tab 循环：

```text
名册 → 档案 → 操作栏 → 名册 → …
```

只保留 `Tab` 正向循环，不提供 `Shift+Tab` 反向循环。切换焦点不改变当前记录或名册滚动位置。

`Workspace.content_panel` 只回答窄屏当前展示名册还是档案，不承担键盘焦点。宽屏始终同时绘制两者；窄屏在工具栏获得焦点时继续展示进入工具栏之前的内容面板。例如从档案按 Tab 到操作栏时：

```text
focus         = TOOLBAR
content_panel = INSPECTOR
```

因此焦点和可见内容不会再次被编码进同一布尔状态。名册聚焦时当前记录用强选中；焦点进入档案或操作栏后，名册当前记录保留弱选中以表达上下文。

## 4. 键盘语义

正常 TUI 只有三类基础交互：

```text
导航      ↑ ↓ ← → / Tab
激活      Enter
撤销      Esc
```

约束：

- Enter 是唯一的通用激活 / 确认键；Space 不再全局等价于 Enter；
- Esc 是唯一的通用取消 / 返回键；`q`、`0`、Backspace 不再充当返回；
- Backspace 只在文本输入中删除字符；
- `J / K` 可以作为 `↓ / ↑` 的终端便利别名，但不形成第二套导航语义；
- `Home / End` 移到当前焦点区域的首 / 尾目标；
- `PageUp / PageDown` 移动当前 viewport，一页之后只在必要时把焦点收回可见区域；
- `Ctrl+C` 属于终端中断，不是界面正常导航命令。

`keys.py` 只把物理输入解码成方向、Enter、Esc、Tab、分页键或原始可打印字符。它不知道“增加”“删除”“导入”等业务含义。

## 5. Command 与快捷键

业务快捷键属于 Command，而不是键盘驱动：

```text
physical key
    ↓
keys.py
    ↓
KeyEvent / printable character
    ↓
当前页面 Command 集合
    ↓
action
```

一个 Command 同时定义：

- `action`：唯一动作身份；
- `label`：界面名称；
- `shortcut`：可选快捷键；
- 是否出现在工具栏。

因此工具栏按钮、鼠标点击、快捷键和在工具栏上按 Enter 最终都产生同一个 action。底栏快捷键提示也从当前可用 Command 自动生成，不手写另一份键位表。

已有记录没有“编辑”Command。进入档案后直接选择可编辑字段并按 Enter 修改，不需要先进入一个虚构的编辑模式。

## 6. 稳定 field target

每个档案字段始终使用：

```text
field:<field_key>
```

例如学生：

```text
field:name              可聚焦 / 只读
field:student_no        可聚焦 / 只读
field:family            可聚焦 / 可编辑
field:branch            可聚焦 / 可编辑
...
```

“可聚焦”和“可编辑”不是同一属性。Enter 激活后再判断权限和 editable；只读字段保持当前 target 并显示提示。

已有记录进入修改时 target 身份不改变。禁止把浏览 target 换成索引 target，或因为进入输入而重建一套字段顺序。

## 7. 已有记录的字段修改

已有记录只有档案，没有编辑页面：

```text
field:<key>
   │ Enter
   ▼
FieldSession
   │ Enter
   ▼
校验 → 保存 → 回到同一 field:<key>
```

- 自由文本 / 数字 / 日期：在原字段位置输入，Enter 立即保存；
- 枚举 / 外键：在原字段下展开 `option:*`，确认后立即保存；
- Esc 取消当前 FieldSession；
- 字段会话期间没有记录级“保存”按钮；
- 保存成功后保持当前记录、档案焦点和字段身份；
- FieldSession 只拥有当前字段或明确的原子复合字段组。

新建记录、删除确认、密码重置、导入 / 导出、seed 是完整事务，仍使用独立 Form / 确认页。

## 8. 学生档案

顺序固定为：

```text
姓名
学号
物种      族系 · 支系
性别
年龄
入学
学院
班级
学籍
元素      主元素 · 亲和

选课与成绩
  …

个人信息
出生日期
联系方式
宿舍
备注
```

性别和年龄各占一行；族系 + 支系属于“物种”复合行；主元素 + 亲和属于“元素”复合行；学号、姓名创建后只读但可聚焦；完整出生日期存在时年龄实时计算，年龄 target 仍可聚焦但直接修改被拒绝；族系与支系作为一个原子 FieldSession 提交。

### 学生二维导航

纵向主链进入复合行时落在右侧成员：

```text
姓名
 ↓
学号
 ↓
族系 ← 支系
       ↓
      性别
      ...
      学籍
       ↓
主元素 ← 亲和
```

因此：

- `姓名 ↓ → 学号`
- `学号 ↓ → 支系`
- `性别 ↑ → 支系`
- `支系 ← → 族系`
- `族系 → → 支系`
- `族系 ← → 学生名册`
- `学籍 ↓ → 亲和`
- `亲和 ← → 主元素`
- `主元素 → → 亲和`
- `主元素 ← → 学生名册`

这些关系从最终可见几何产生，`events.py` 不硬编码学生字段名称。

## 9. 普通实体档案

学院、专业、班级、课程、成绩等普通档案默认单列：

```text
A
↓
B
↓
C
```

`↑ / ↓` 纵向移动；`→` 留在当前单列 target；`←` 返回名册；Enter 在可编辑字段创建 FieldSession。公告复用同一工作台，只按权限限制写操作。

## 10. 最终几何与响应式

档案内容必须先完成终端换行和 compact 布局，再提取 target：

```text
content
  ↓
wrap / layout
  ↓
final lines
  ├─ draw
  ├─ click
  └─ arrows
```

因此宽度变化可能改变实际空间关系，但绘制和导航永远同步。不能让方向键继续按照换行前的“逻辑行”运行。

名册的可见记录容量也由同一个 `WorkspaceLayout` 计算。列标题占用的行必须从名册容量中扣除；绘制、Home / End 和 PageUp / PageDown 不能各自假设不同的可见行数。

## 11. 鼠标与滚轮

右侧档案未聚焦时，滚轮只移动预览视口，不抢左侧焦点；右侧档案已聚焦时：

```text
wheel up   → up
wheel down → down
```

然后与键盘进入同一个空间导航函数。

## 12. 文本输入

`TextBuffer` 是文本、光标和可见窗口的唯一状态模型。输入期间普通字母、空格、`/`、`q` 等都属于文本；`← / →` 移动光标；Backspace / Delete 删除字符；Enter 确认；Esc 取消；中文和宽字符按终端 cell 宽度处理。

## 13. 返回与取消

Esc 始终退出最内层状态：FieldSession 输入 / 选项 → 完整事务 Form → 档案焦点 → 工具栏焦点 → 关联来源 → 首页。

不为 `q`、`0`、Backspace 等建立第二套返回路径。

## 14. 颜色语义

颜色值只在 `tui/tokens.py` 定义。组件组合语义 token，不创建历史别名。

- `surface-selected + text-on-selected`：当前键盘 target；
- `surface-interactive + text-primary`：当前记录但焦点在其他区域；
- `text-accent`：页面与重点；
- `text-secondary`：标签与说明。

统一来自语义一致，而不是把所有内容染成同一种强调色。
