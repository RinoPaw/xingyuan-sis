# Terminal UI 设计规范

本文档规定星原 SIS 当前 TUI 的视觉与交互语义，只描述现在成立的设计。

## 1. 设计目标

1. 同一时刻只有一个明确键盘焦点；
2. “当前位置”“当前记录”“当前焦点”使用不同语义；
3. 宽窄终端可以重新排布，但操作含义不变；
4. 一个字段只有一个稳定身份和一套展示规则；
5. 文本输入期间普通字符不被全局快捷键截获；
6. 鼠标与键盘表达同一个意图时进入同一处理路径；
7. 用户看到的最终屏幕几何就是方向键使用的几何。

## 2. 门户与工作台

登录后的 TUI 由 `app.py + portal.py` 唯一负责。管理员和学生共享门户结构，只按权限显示不同入口。

记录型页面共享：

```text
工具栏 / 视图

名册                     档案
当前记录                 字段与关联

状态栏
底栏
```

宽屏名册与档案并列；窄屏单面板展开，但仍属于同一个 `Workspace`。

## 3. 焦点模型

必须区分：当前位置、当前记录、键盘焦点。名册聚焦时当前记录用强选中；焦点进入档案后，名册当前记录保留弱选中以表达上下文。

`Tab / Shift+Tab` 在名册、档案与工具栏之间循环，不改变当前记录。

## 4. 稳定 field target

每个档案字段始终使用：

```text
field:<field_key>
```

例如学生：

```text
field:name              可聚焦 / 只读
field:student_no        可聚焦 / 只读
field:family            可聚焦 / 可编辑
field:branch            可聚焦 / 可编辑
...
```

“可聚焦”和“可编辑”不是同一属性。Enter 激活后再判断权限和 editable；只读字段保持当前 target 并显示提示。

已有记录进入修改时 target 身份不改变。禁止把浏览 target 换成索引 target，或因为进入输入而重建一套字段顺序。

## 5. 已有记录的字段修改

已有记录只有档案，没有编辑页面：

```text
field:<key>
   │ Enter
   ▼
FieldSession
   │ Enter
   ▼
校验 → 保存 → 回到同一 field:<key>
```

- 自由文本 / 数字 / 日期：在原字段位置输入，Enter 立即保存；
- 枚举 / 外键：在原字段下展开 `option:*`，确认后立即保存；
- Esc 取消当前 FieldSession；
- 字段会话期间没有记录级“保存”按钮；
- 保存成功后保持当前记录、档案焦点和字段身份；
- FieldSession 只拥有当前字段或明确的原子复合字段组；
- 顶部“编辑”只把焦点移到第一个可编辑 field，不打开页面。

新建记录、删除确认、密码重置、导入 / 导出、seed 是完整事务，仍使用独立 Form / 确认页。

## 6. 学生档案

顺序固定为：

```text
姓名
学号
物种      族系 · 支系
性别
年龄
入学
学院
班级
学籍
元素      主元素 · 亲和

选课与成绩
  …

个人信息
出生日期
联系方式
宿舍
备注
```

性别和年龄各占一行；族系 + 支系属于“物种”复合行；主元素 + 亲和属于“元素”复合行；学号、姓名创建后只读但可聚焦；完整出生日期存在时年龄实时计算，年龄 target 仍可聚焦但直接修改被拒绝；族系与支系作为一个原子 FieldSession 提交。

### 学生二维导航

纵向主链进入复合行时落在右侧成员：

```text
姓名
 ↓
学号
 ↓
族系 ← 支系
       ↓
      性别
      ...
      学籍
       ↓
主元素 ← 亲和
```

因此：

- `姓名 ↓ → 学号`
- `学号 ↓ → 支系`
- `性别 ↑ → 支系`
- `支系 ← → 族系`
- `族系 → → 支系`
- `族系 ← → 学生名册`
- `学籍 ↓ → 亲和`
- `亲和 ← → 主元素`
- `主元素 → → 亲和`
- `主元素 ← → 学生名册`

这些关系从最终可见几何产生，`events.py` 不硬编码学生字段名称。

## 7. 普通实体档案

学院、专业、班级、课程、成绩等普通档案默认单列：

```text
A
↓
B
↓
C
```

`↑ / ↓` 纵向移动；`→` 留在当前单列 target；`←` 返回名册；Enter 在可编辑字段创建 FieldSession。公告复用同一工作台，只按权限限制写操作。

## 8. 最终几何与响应式

档案内容必须先完成终端换行和 compact 布局，再提取 target：

```text
content
  ↓
wrap / layout
  ↓
final lines
  ├─ draw
  ├─ click
  └─ arrows
```

因此宽度变化可能改变实际空间关系，但绘制和导航永远同步。不能让方向键继续按照换行前的“逻辑行”运行。

## 9. 鼠标与滚轮

右侧档案未聚焦时，滚轮只移动预览视口，不抢左侧焦点；右侧档案已聚焦时：

```text
wheel up   → up
wheel down → down
```

然后与键盘进入同一个空间导航函数。

## 10. 文本输入

`TextBuffer` 是文本、光标和可见窗口的唯一状态模型。输入期间普通字母、`/`、`q` 等都属于文本；`← / →` 移动光标；Enter 确认；Esc 取消；中文和宽字符按终端 cell 宽度处理。

## 11. 返回与取消

Esc 始终退出最内层状态：FieldSession 输入 / 选项 → 完整事务 Form → 档案焦点 → 工具栏焦点 → 关联来源 → 首页。

终端层可以接受额外便利输入，但 UI 不为它们建立第二套导航状态机。

## 12. 颜色语义

颜色值只在 `tui/tokens.py` 定义。组件组合语义 token，不创建历史别名。

- `surface-selected + text-on-selected`：当前键盘 target；
- `surface-interactive + text-primary`：当前记录但焦点在其他区域；
- `text-accent`：页面与重点；
- `text-secondary`：标签与说明。

统一来自语义一致，而不是把所有内容染成同一种强调色。
