# Terminal UI 设计规范

本文档规定星原 SIS 当前 TUI 的视觉与交互语义。它描述**现在应该成立的设计**，不记录已经淘汰的实现路径。

## 1. 设计目标

终端界面首先要让用户形成稳定的空间与操作模型：

1. 同一时刻只有一个明确的键盘焦点；
2. “当前位置”“当前记录”“当前焦点”使用不同语义；
3. 宽窄终端可以重新排布，但操作含义不变；
4. 同一概念只有一个 renderer / 状态模型；
5. 文本输入期间，普通字符不被全局快捷键截获；
6. 鼠标与键盘表达同一个交互意图时必须进入同一处理路径。

## 2. 门户与工作台

登录后的 TUI 由 `app.py + portal.py` 负责。管理员和学生共享同一套门户结构，只根据权限显示不同入口。

记录型页面共享工作台：

```text
工具栏 / 视图

名册                     档案
当前记录                 当前记录的字段与关联

状态栏
底栏
```

宽屏时名册与档案并列；窄屏时可单面板展开，但仍属于同一个 `Workspace` 状态机。

## 3. 焦点模型

必须区分：

- **当前位置**：当前页面 / 栏目；
- **当前记录**：名册中为右侧档案提供内容的记录；
- **键盘焦点**：方向键和 Enter 此刻作用的位置。

名册获得焦点时，当前记录使用强选中表面；焦点进入档案后，名册中的当前记录保留弱选中态，继续表达上下文。

`Tab / Shift+Tab` 在名册、档案与工具栏之间循环；切换区域不改变当前记录。

## 4. 字段 target 与编辑能力

“能被选中”和“能被编辑”不是同一个属性。

浏览态每个档案字段都有稳定的：

```text
field-target:<field_key>
```

因此只读字段仍是档案空间的一部分。例如学生：

```text
姓名      可聚焦 / 只读
学号      可聚焦 / 只读
族系      可聚焦 / 可编辑
支系      可聚焦 / 可编辑
...
```

Enter 只在当前字段可编辑且当前身份有写权限时进入编辑。只读字段按 Enter 后仍停在原 target，并给出只读提示。

这条规则适用于所有记录页，不为学生页面维护第二套“只读选择”逻辑。

## 5. 已有记录的字段修改

已有记录的展示和修改属于**同一个档案页面、同一条选择链**。

```text
field-target
   │ Enter
   ▼
输入框 / 选项列表
   │ Enter
   ▼
校验 → 保存 → 回到原 field-target
```

规则：

- 自由文本 / 数字 / 日期：Enter 进入原位置输入，第二次 Enter 立即校验并保存；
- 枚举 / 外键：Enter 在原字段处展开选项，确认后立即保存；
- Esc 取消当前字段修改，不写数据库；
- 字段编辑期间没有记录级“保存”按钮；
- 保存成功后保持当前记录、档案焦点和字段位置；
- 当前字段会话只拥有当前字段及明确声明的复合字段，不复制整条记录。

新建记录仍是多字段事务，因此保留完整表单和显式保存。删除、密码重置、seed 等操作继续使用确认页。

顶部“编辑”动作只把焦点带到第一个可编辑字段，不打开第二套编辑页面。

## 6. 学生档案

学生档案顺序固定为：

```text
姓名
学号
物种      族系 · 支系
性别
年龄
入学
学院
班级
学籍
元素      主元素 · 亲和

选课与成绩
  …

个人信息
出生日期
联系方式
宿舍
备注
```

约束：

- 性别和年龄各占一行；
- 族系 + 支系属于同一个“物种”复合行；
- 主元素 + 亲和属于同一个“元素”复合行；
- 学号、姓名创建后只读，但仍可聚焦；
- 出生资料支持 `YYYY-MM-DD`、`YYYY`、`--MM-DD`；
- 完整出生日期存在时，年龄实时计算；年龄 target 仍可被选中，但不能直接修改，应修改出生日期；
- 出生资料不完整时，可以直接维护独立年龄；
- 族系与支系作为一个原子复合编辑提交。

### 学生二维导航

纵向主链进入复合行时落在**右侧成员**：

```text
姓名
 ↓
学号
 ↓
族系 ← 支系
       ↓
      性别
      ...
      学籍
       ↓
主元素 ← 亲和
```

因此：

- `姓名 ↓ → 学号`
- `学号 ↓ → 支系`
- `支系 ↑ → 学号`
- `性别 ↑ → 支系`
- `支系 ← → 族系`
- `族系 → → 支系`
- `族系 ← → 返回学生名册`
- `学籍 ↓ → 亲和`
- `亲和 ↑ → 学籍`
- `亲和 ← → 主元素`
- `主元素 → → 亲和`
- `主元素 ← → 返回学生名册`

这套几何由 inspector 的真实行结构产生，事件层不硬编码“学生”“物种”“元素”。

## 7. 其他实体档案

学院、专业、班级、课程、成绩等普通档案默认是单列 target：

```text
A
↓
B
↓
C
```

- `↑ / ↓` 在纵向移动；
- `→` 保持当前 target；
- `←` 从当前单列 target 返回名册；
- Enter 在可编辑字段进入单字段修改；
- 只读字段仍可聚焦，但不会进入编辑。

公告复用同一工作台与只读焦点语义；正文可滚动阅读到最后。

## 8. 鼠标与滚轮

右侧档案**未获得焦点**时，滚轮只移动档案预览视口，不抢夺左侧名册焦点。

右侧档案**已经获得焦点**时：

```text
wheel up   → up
wheel down → down
```

随后与键盘方向键调用同一个档案 target 导航入口。不得再建立“滚轮修改 scroll、方向键修改 selected”的两套聚焦档案行为。

## 9. 文本输入

`TextBuffer` 是文本值、光标和可见窗口的唯一状态模型。

进入文本输入后：

- 普通字母、`/`、`q` 等都属于文本；
- `← / →` 移动文本光标；
- Enter 确认；
- Esc 取消；
- 中文、组合字符和宽字符按终端 cell 宽度处理。

## 10. 返回与取消

Esc 始终退出当前最内层状态：

- 输入 / 选项：取消当前字段；
- 确认 / 新建表单：取消当前事务；
- 档案焦点：返回名册；
- 工具栏焦点：退出工具栏；
- 关联浏览：返回来源记录；
- 首页：退出 TUI。

终端层可以继续接受 `q`、`0`、`Ctrl+C` 等便利输入，但 UI 不把它们发展成第二套导航模型。

## 11. 颜色语义

颜色值只在 `tui/tokens.py` 定义。组件组合语义 token，不创建 `_ACCENT`、`_SELECTED` 等第二套历史命名。

焦点主要依靠：

- `surface-selected + text-on-selected`：当前键盘 target；
- `surface-interactive + text-primary`：当前记录但焦点在其他区域；
- `text-accent`：页面 / 重点；
- `text-secondary`：标签与说明。

统一来自语义一致，而不是把所有内容染成同一种强调色。
