# Terminal UI 设计规范

本文档定义星原 SIS 交互式终端界面的视觉语义。规范采用成熟设计系统中的 **semantic / functional token** 思路，再根据终端的 ANSI 颜色、等宽字符和有限交互能力做适配。

## 1. 参考基线

本规范主要参考：

- [GitHub Primer — Color usage](https://primer.style/product/getting-started/foundations/color-usage/)：采用 Base → Functional → Component/Pattern 的 token 分层。布局代码优先使用语义/功能 token，不直接依赖原始色号。
- [IBM Carbon — Color tokens](https://carbondesignsystem.com/elements/color/tokens/)：参考 `text-primary`、`text-secondary`、`border-subtle`、`background` 等按角色命名的颜色体系，以及“标题属于 primary text、标签属于 secondary text”的层级关系。
- [Charm Lip Gloss](https://github.com/charmbracelet/lipgloss)：参考终端环境对 ANSI 16、ANSI 256、TrueColor 和自适应颜色的能力边界。星原 SIS 当前直接输出 ANSI，不依赖 Lip Gloss 本身。

这些系统提供的是设计方法和语义模型。星原 SIS 的具体色号、动画和排版仍属于本项目自己的视觉语言。

## 2. 核心原则

**先决定信息角色，再决定视觉值。**

代码和设计讨论中应使用 `text-primary`、`text-secondary`、`text-accent`、`surface-*`、`border-subtle` 这样的语义角色。`xterm 252`、`xterm 248` 等数字只是当前暗色主题的一种实现，不承担语义。

同一个原始颜色可以服务多个相近角色，但不能因为“看起来差不多”就把不同信息层级合并。反过来，同一个语义 token 将来可以在不同终端能力或主题下映射到不同色值。

## 3. 语义 token

### 文本

| Token | 语义 | 典型内容 |
| --- | --- | --- |
| `text-primary` | 主要信息 | 正文、区块标题、主要字段值 |
| `text-secondary` | 次要/辅助信息 | 字段标签、说明、面包屑、辅助统计标签 |
| `text-accent` | 当前状态、焦点、重要强调 | 当前页面、当前导航项、少量关键统计值 |
| `text-on-selected` | 高亮背景上的焦点文字；颜色与 `text-accent` 相同 | 选中行、选中按钮 |

### 表面与结构

| Token | 语义 | 典型内容 |
| --- | --- | --- |
| `surface-default` | 页面主背景 | 主工作区 |
| `surface-topbar` | 顶栏表面 | 顶部应用栏 |
| `surface-footer` | 底栏表面 | 底部操作栏 |
| `surface-interactive` | 普通可点击表面 | 按钮、失焦但仍需保留上下文的当前项 |
| `surface-selected` | 当前选择 | 高亮行、选中按钮 |
| `border-subtle` | 弱结构边界 | 分隔线、低强调边框 |

装饰性颜色（例如首页轨道的金色）不属于信息层级 token；它们只能用于视觉装饰，不能代替状态色或正文色。

## 4. 信息层级

从高到低按以下语义处理：

1. **当前页面标题 / 当前导航项**：`text-accent` + 粗体。例：`01 / 学生档案`、当前选中的 `1 学生`。
2. **区块标题**：`text-primary` + 粗体。例：`校园概览`、`详细信息`。
3. **关键值**：默认属于 `text-primary`；确实需要快速扫读的少量统计值可以使用 `text-accent` + 粗体。
4. **普通正文 / 普通导航项**：`text-primary`，通常不额外加粗。
5. **字段标签 / 说明文字 / 次级位置提示**：`text-secondary`。
6. **结构分隔符**：`border-subtle`，不得比字段标签更抢眼。

标题、标签和值是不同角色。尤其禁止仅因为它们位于同一区域，就使用完全相同的样式。

## 5. 首页示例

首页左侧应形成明确的层级：

```text
首页                 ← text-secondary
▌ 1 学生             ← text-accent + bold
  2 教务             ← text-primary
  3 课程
...

校园概览             ← text-primary + bold
学生 100   班级 26   ← 标签 text-secondary；关键数字可 text-accent + bold
课程 20    选课 400
```

因此 `校园概览` 与 `学生 / 班级 / 课程 / 选课` 必须有明显的视觉差异。前者是 section heading，后者是 label。

### 一级 / 二级导航

一级菜单获得焦点时，只有当前一级项表达焦点，例如 `▌ 教务`。右侧二级菜单此时只是**预览**：二级项使用普通 `text-primary` 文本，不使用方括号、整块灰色按钮背景或任何“当前项”样式。即使程序内部记住了上一次二级选择，也不得显示蓝色文字或其他焦点提示，以免制造第二个焦点。

进入二级菜单后，一级项降为弱上下文 `▏ 教务`；真正获得键盘焦点的二级项使用 `text-accent` + 粗体 + 下划线，不再额外添加 `>` / `›`、方括号或整块选中背景。也就是说：`▌` 表示当前一级焦点，`▏` 表示当前所属一级栏目；二级焦点由蓝色文字与下划线共同表达。

二级菜单采用紧凑内容宽度布局，不把每个项目拉伸到整列宽度。宽度足够时尽量在同一行展示更多项目；空间不足再自然换行。这样二级导航保持轻量，不与工作区中的表格、表单按钮争夺视觉重量。

无论控件使用导航竖条、下划线、整行背景或输入框背景来辅助表达，**真正的当前焦点 / 选中文字统一使用蓝色强调色**。不得再出现一级菜单蓝色、二级按钮白色、工作区选中行白色等页面级配色分叉；这些状态统一通过 `text-accent` / `text-on-selected` 映射到同一个颜色。

门户底栏是固定导航契约，不随一级 / 二级菜单、当前一级项或“退出登录”等状态变化。统一显示 `[ 方向键 移动 ]   [ Enter 确认 ]   [ Esc 返回 ]`。实际动作可以按当前层级执行，但底栏不得再改成“进入”“打开”“退出登录”“返回 / 退出”等状态化文案。

## 6. 工作区页面

学生、学院、专业、班级、课程、成绩和数据页共享同一套信息层级。

学生页不再设置“全部档案 / 在读学生 / 未分班”三组顶部快捷分类，避免与结构化搜索形成两套筛选模型。标题下直接进入搜索：

```text
学生档案                         ← 当前页面，text-accent + bold
/ 搜索；支持 --name / --class / --year …

▌ 名册                           ← 当前获得键盘焦点的面板
姓名  学号  班级                 ← 列标签 text-secondary
林岚  20260001 ...               ← 当前记录使用 surface-selected + text-on-selected

  档案                           ← 未获得焦点，保持正常标题层级
```

学生搜索与 `xy stu ls` 共用同一套结构化查询条件和解析规则。支持 `--no`、`--name`、`--family`、`--branch`、`--class`、`--major`、`--college` / `--department`、`--year`、`--status`、`--element`、`--affinity` 以及 `-s` / `--search`。不同字段按 AND，同一字段重复按 OR；学号和年份精确匹配，其他结构化文本条件按包含匹配。TUI 额外允许直接输入裸文本，等价于全文搜索，并可与结构化条件混合，例如 `赤狐 --year 2025 --status 在读`。

宽屏双栏必须明确区分“记录选择”和“面板焦点”。左侧高亮行表示当前记录，即使焦点切到右侧也继续保留；右侧获得焦点后，左侧当前记录降为 `surface-interactive + text-primary`，只承担上下文提示，不与右侧操作焦点竞争。获得焦点的面板标题使用 `▌` + `text-accent` + 粗体，另一侧标题保持 `text-primary`。名册面板已经用 `▌` 表达焦点，因此选中记录本身不再重复添加第二根竖条，只使用选中表面和蓝色文字。

左右方向键作为面板焦点的定向快捷方式：`→` 选择右侧档案面板，`←` 选择左侧名册。它们必须是幂等的——已经位于右侧时继续按 `→` 不应切回左侧，已经位于左侧时按 `←` 也不应离开当前页面。`Tab` 继续保留为双向切换键。为了保持提示简洁，底栏只展示 `Tab 切换`，无需并列罗列所有等价快捷键。

### 档案信息组织

右侧档案只承担三件事：**识别当前记录、浏览关联记录、查看补充信息**。焦点状态已经由面板状态和选中表面表达，因此不得再增加“即时预览”“阅读中”或 `>` / `›` 这类重复焦点提示。

学生档案使用“摘要 → 选课与成绩 → 详细信息”的结构：

```text
▌ 档案

林岚  20260001
猫科 · 石虎        2026级 · 在读
风 · A             元素学2601班
自然科学学院

选课与成绩  04
  元素现象导论 · 79
  元素场分析 · 83      ← 当前可交互项使用 surface-selected + text-on-selected
  程序设计基础 · 62

详细信息
性别          女
出生日期      2007-06-08
联系方式      —
宿舍          北区 2-113
备注          —
```

摘要负责高频识别信息，同一字段不得在下方再次机械重复。学生页的 `姓名 / 学号 / 族系 / 支系 / 入学年份 / 学籍 / 主元素 / 亲和等级 / 班级 / 学院` 属于摘要；`性别 / 出生日期 / 联系方式 / 宿舍 / 备注` 属于补充信息。整份档案仍可通过页面编辑动作修改，右侧补充字段也可以作为快捷编辑入口。

右侧所有能够执行动作的项目（关联记录、可编辑的补充字段、成绩等）属于同一个键盘选择序列。获得右侧焦点后，`↑/↓` 在这些可交互项之间移动，当前项使用 `surface-selected + text-on-selected`，不添加额外箭头；`Enter` 执行当前项。滚动时应保持当前选择与可见区域一致，不能只改变文字状态却不给出明确的选中反馈。

其他实体页面沿用“摘要 → 关联记录 → 补充属性”的信息逻辑，但摘要字段按实体本身设计，不应为了复用组件把数据库字段原样全部重复展示。

课程页和成绩页可以保留与业务直接对应的视图筛选；学院 / 专业 / 班级导航的记录数也与对应导航项绑定。若某项统计没有一一对应的交互目标，例如数据总览中的学生数、课程数和选课数，则可以保留独立统计摘要。

筛选数量应反映当前搜索条件下切换到该视图后实际会得到的记录数。当前面板焦点可以使用强调色，但不能把该面板内部的标题、标签和值全部染成强调色。

## 7. 强调色

强调色用于表达**当前、可操作焦点或真正重要的值**，不能成为“看起来更漂亮”的通用文字颜色。

优先使用场景：

- 当前页面标题；
- 当前导航项；
- 键盘/鼠标焦点；
- 少量需要立即扫读的关键统计值；
- 明确的交互强调。

普通 section heading 使用 `text-primary`，说明文字和字段标签使用 `text-secondary`。如果页面上大面积文字都变成强调色，说明语义层级已经失效。

确认、删除、待录入等状态首先依赖明确文案和结构表达。错误与不可逆删除使用 `text-danger`（xterm 217），并辅以明确文案和 `!` 标记；不得借用 decorative gold 冒充状态色。

## 8. 当前暗色主题映射

```text
_SURFACE_FOOTER

_SURFACE_SELECTED
```

登录、首页与工作台统一使用 `theme.topbar`：左侧为 `✦ 星原 SIS`，右侧身份和数据库信息属于次级文字。字段标签定宽对齐，关联字段显示名称和业务编号。一级导航用竖条表达层级焦点；二级导航使用蓝色粗体下划线；名册行、详情操作和选择器使用蓝色文字配合选中表面，不再额外堆叠箭头或第二根竖条。

窄屏视图按钮优先显示完整名称与数量，空间不足时简化为编号与数量；所有视图仍保留点击入口。短窗口导航滚动显示当前选项。

组件和页面不得再定义第二套“看起来差不多”的正文/强调颜色。

## 9. 返回与取消

`Esc` 是默认 TUI 中唯一需要对用户展示的返回/取消键。

- 浏览页面按 `Esc` 返回上一层；首页按 `Esc` 退出。
- 详情、选择器、表单等嵌套状态按 `Esc` 只取消当前最内层状态，再次按 `Esc` 才继续返回上一层。
- 文本输入模式中，普通字母都属于输入内容，`q`、`/` 等不得继续承担返回语义；`Esc` 取消本次输入并恢复进入输入前的状态。
- `q`、`0`、`Ctrl+C` 可以作为兼容或终端习惯保留，但 UI 不并列展示多个等价退出键。
- 提示文案避免写成 `q / Esc / Ctrl+C 取消` 这类快捷键堆叠。底栏和就地提示统一只显示 `Esc`。

这样可以让用户形成稳定的层级模型：`Esc` 始终意味着“退出当前这一层”，无需记忆当前页面到底使用哪一个退出键。

## 10. 终端约束

星原 SIS 当前以 ANSI 256 色作为稳定基线。不要假设所有用户都有 TrueColor，也不要要求用户修改 Windows Terminal、Termux 或其他宿主终端的主题。

状态强调不应只靠单一前景色：一级导航使用层级竖条，二级导航使用下划线，列表和操作项使用选中表面，文本输入使用输入框表面。避免为同一个状态重复叠加多个相同作用的符号。

窄屏可以重新排布布局，但语义层级保持不变：页面标题仍高于区块标题，区块标题仍高于字段标签。

## 11. 实现约束

布局代码不得为了临时视觉效果散落新的 ANSI 色号。新增样式时按以下顺序处理：

1. 判断内容的语义角色；
2. 优先复用已有 semantic token；
3. 只有现有角色确实无法表达时才新增 token；
4. 最后为 token 选择 ANSI 映射。

如果一个视觉调整改变了标题、正文、标签、焦点、选中态或关键值之间的层级关系，应同步检查并更新本文档。
