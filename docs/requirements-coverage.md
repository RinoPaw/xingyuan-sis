# 需求覆盖与交付说明

依据仓库中的《Python项目开发实践指导书 V1.9.doc》第一部分，以及本次学生页面、全站交互和架构要求整理。

## 交付范围

交付现有终端系统的完整功能：CLI、数字输入基础菜单、即时键盘 TUI，数据保存在 SQLite。学生、学院、专业、班级、课程、成绩、公告和数据工作台均纳入本轮重构与验证。

指导书中的内存、JSON、SQLite 是课程递进阶段，本项目使用 SQLite 持久化。后续 Tkinter GUI、Flask Web 等章节属于另外的应用形态，本轮未实现，不计入当前终端版的完成范围。

## 需求对应

| 要求 | 当前实现 |
| --- | --- |
| 初始化管理员、登录、退出 | `Administrator` 首次设密；三种入口共用认证与权限规则 |
| 管理员增加学生并分配初始密码 | 新增与 CSV 导入原子写入档案和密码散列；成功后显示对应学号及初始密码 |
| 学生首次登录必须改密 | 初始密码和管理员重置后的密码均要求修改；新密码不能与当前密码相同 |
| 学号只能为数字 | 统一字段契约只接受 `0–9`，保留前导零；拒绝字母、符号、科学计数法与其他字符集数字 |
| 按学号、姓名查询 | 精确学号、姓名包含匹配；TUI 与 CLI 共享查询语法 |
| 管理员不能修改学号、姓名 | 创建后只读；服务层拒绝变更，界面与 CLI 不提供修改入口 |
| 学生只修改自己的密码 | 学生使用只读工作台；基础菜单、CLI 和 TUI 均限制管理操作 |
| 班级公告 | 管理员发布、阅读、删除；学生按当前班级读取，转班后随之切换，未分班时为空 |
| 数据持久化与导入导出 | SQLite、CSV；逐行报告失败，成功行返回初始密码，导出不包含密码或散列 |
| 完整的纯键盘操作 | 区域焦点循环、关联返回、原地编辑、选项取消、保存和删除确认 |

指导书列出的住址、电话、邮件、籍贯、爱好等是个人资料示例。当前保留星原档案模型，通过联系方式、宿舍与备注记录相关资料；年龄由出生日期推导，不重复存储独立年龄字段。

## 操作逻辑

- 浏览时 `Tab / Shift+Tab` 在名册、档案和工具栏之间循环，当前记录与滚动位置保持不变。名册首项按 ↑ 仍可进入工具栏，但删除任意学生无需先回首项。
- 删除：选中学生 → `Shift+Tab` → 工具栏“删除” → Enter → 核对姓名与学号 → Enter 确认。`d` 打开同一确认页，Esc 取消。
- 编辑：在档案原有字段位置操作；`Tab / Shift+Tab` 遍历字段和保存按钮，Enter 输入或确认，`s` 保存。字段暂存不写数据库，Esc 逐层取消。
- 关联浏览返回时恢复来源记录、筛选、视图、滚动和焦点。学生查询与个人资料复用同一套只读档案。
- 窄屏工具栏随焦点滚动；短窗口表单保留当前字段和保存入口；长公告、档案尾部和导入错误可滚动读完。

## 本轮发现并修正的问题

| 问题 | 修正 |
| --- | --- |
| 工具栏只能从名册首项按 ↑ 到达，难以删除任意选中的学生 | 增加双向区域焦点循环，保留当前记录 |
| 非学生页面拥有另一套编辑布局和字段导航规则 | 共用档案绘制、字段、选项、可见区和导航；内容层保留实体差异 |
| 基础菜单的命令执行可能绕过正式入口认证 | 唯一命令入口收敛到 `entry.main` |
| 学生新增和 CSV 导入未完成初始账号交付 | 注册服务原子创建档案与账号；各入口展示成功记录的初始密码 |
| CSV 自行访问数据库、重复关联校验 | CSV 只负责解析与输出，由服务处理注册和校验 |
| 首次改密可继续使用原始密码 | 拒绝与当前密码相同的新密码 |
| 学号可包含非数字，与账号规则存在冲突 | 使用统一数字字符串契约，同时排除 `Administrator` 等非数字账号名 |
| 短窗口可能遮住当前字段、保存按钮或导入错误 | 统一可见区计算并测试极短窗口 |
| 只读档案焦点被关联链接吸住，无法继续阅读尾部 | 滚动与可见动作选择分离 |
| 切换族系后残留不属于新族系的支系 | 清空不兼容支系，要求重新选择 |
| 删除班级的影响不够明确 | 确认页说明学生将变为未分班，以及被删除的公告数量 |
| 名册仅用颜色表现当前记录 | 增加强、弱记录标记，区分焦点和当前上下文 |

## 架构边界

`schema` 定义字段及校验；`service` 处理业务规则与关联；`repository` 处理业务数据 SQL；`auth` 负责账号与会话。CLI、基础菜单和 TUI 共享这些规则。

工作台中，`student_inspector` 与 `detail` 只定义内容；`inspector` 统一绘制与可见区；`forms` 处理草稿；`events` 处理交互；`view` 编排布局。删除不再使用的私有转发入口，测试直接验证当前生产路径。

## 验证与边界

本轮 203 项自动测试全部通过，覆盖全部工作台、实体编辑、纯键盘选中删除、取消、关联返回、不同窗口尺寸、只读权限、账号交付、公告范围和 CSV 部分失败。测试使用临时数据库与认证目录；Ruff 正确性规则与 `git diff --check` 同样通过。

Linux 伪终端冒烟检查覆盖真实按键解码、门户进入八个工作台、删除确认与取消、长公告及退出后终端恢复。另检查宽屏和短窗口的实际渲染帧。

Windows 扩展按键已支持 Shift+Tab、PageUp、PageDown；本环境未运行 Windows 真实终端，仍需在目标 Windows Terminal / 控制台验收。公告正文可保存多行并换行阅读，但 TUI 当前使用单行输入器；复杂多段正文可通过 CLI 的 `--body` 参数传入。

本轮只追加公告表，不重建现有数据库，也不自动改写历史学号。现有本地库的 100 条学生学号经只读检查均符合数字规则。历史版本缺列的数据库仍遵循项目原有策略：显式重建或另外实施迁移，不能将初始化当作隐式迁移。
