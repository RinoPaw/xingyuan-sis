# 需求覆盖与交付说明

依据仓库中的《Python项目开发实践指导书 V1.9.doc》第一部分，以及当前学生页面、全站交互和架构要求整理。

## 交付范围

交付现有终端系统的完整功能：CLI、数字输入基础菜单、即时键盘 TUI，数据保存在 SQLite。学生、学院、专业、班级、课程、成绩、公告和数据工作台均纳入当前实现与验证。

指导书中的内存、JSON、SQLite 是课程递进阶段，本项目使用 SQLite 持久化。后续 Tkinter GUI、Flask Web 等章节属于另外的应用形态，不计入当前终端版的完成范围。

## 需求对应

| 要求 | 当前实现 |
| --- | --- |
| 初始化管理员、登录、退出 | `Administrator` 首次设密；三种入口共用认证与权限规则 |
| 管理员增加学生并分配初始密码 | 新增与 CSV 导入原子写入档案和密码散列；成功后显示对应学号及初始密码 |
| 学生首次登录必须改密 | 初始密码和管理员重置后的密码均要求修改；新密码不能与当前密码相同 |
| 学号只能为数字 | 统一字段契约只接受 `0–9`，保留前导零；拒绝字母、符号、科学计数法与其他字符集数字 |
| 按学号、姓名查询 | 精确学号、姓名包含匹配；TUI 与 CLI 共享查询语法 |
| 管理员不能修改学号、姓名 | 创建后只读；服务层拒绝变更，界面与 CLI 不提供修改入口 |
| 学生只修改自己的密码 | 学生使用只读工作台；基础菜单、CLI 和 TUI 均限制管理操作 |
| 班级公告 | 管理员发布、阅读、删除；学生按当前班级读取，转班后随之切换，未分班时为空 |
| 数据持久化与导入导出 | SQLite、CSV；逐行报告失败，成功行返回初始密码，导出不包含密码或散列 |
| 完整的纯键盘操作 | 单向 Tab 区域焦点循环、方向导航、关联返回、原地字段修改、选项取消和事务确认 |

指导书列出的住址、电话、邮件、籍贯、爱好等是个人资料示例。当前保留星原档案模型，通过联系方式、宿舍与备注记录相关资料；完整出生日期存在时年龄实时派生，资料不完整时允许保存独立年龄。

## 操作逻辑

- 浏览记录型页面时，`Tab` 单向循环 `名册 → 档案 → 操作栏 → 名册`，当前记录与名册滚动位置保持不变；不提供 Shift+Tab 第二条区域切换路径。
- 新建：新增档案的提交按钮固定在档案底部。保存成功后原位置直接转换为浏览档案，焦点继续留在档案；新记录按真实排序位置插入左侧名册。
- 删除：使用工具栏“删除”或 `d` 打开档案侧确认页；确认删除后焦点回到名册，但不会自动选择相邻学生：原记录位置保留一个临时空槽，右侧显示“当前未选择学生”；`↑` 选择删除前一位，`↓` 选择删除后一位。Esc 取消确认。
- 修改已有记录：进入档案，方向键选择字段，Enter 在原字段建立 `FieldSession`；文本或选项确认后立即校验并保存，没有记录级“编辑模式”或“保存”按钮。
- 新建、删除确认、密码重置、导入 / 导出和 seed 属于完整事务，继续使用 `Form`；Form 内 Tab 也只向前循环字段和确认目标。
- 关联浏览返回时恢复来源记录、筛选、视图、滚动、`FocusArea` 和窄屏 `ContentPanel`。学生查询与个人资料复用同一套只读档案。
- 宽屏名册与档案同时存在；窄屏只显示一个内容面板。操作栏焦点与当前内容面板分离，因此按 Tab 到操作栏不会让正在查看的内容突然切面。
- 名册、档案的 PageUp / PageDown 都使用各自真实可见容量；名册列标题占用的行只在 `WorkspaceLayout` 中计算一次。

## 当前交互模型解决的问题

| 问题 | 当前设计 |
| --- | --- |
| `details + action_focus` 两个布尔状态可形成无意义组合 | 使用唯一 `FocusArea` 表示键盘焦点 |
| 焦点和窄屏“当前显示哪一面”互相牵动 | 独立 `ContentPanel` 只负责窄屏内容 |
| Tab 与 Shift+Tab 维护两套区域切换 | 只保留 Tab 单向循环 |
| 工具栏只能从名册首项按 ↑ 到达 | Tab 可从任意当前记录稳定到达操作栏，并保留当前记录 |
| 非学生页面拥有另一套编辑布局和字段导航规则 | 共用档案绘制、字段、选项、可见区和导航；内容层保留实体差异 |
| 已有记录编辑需要整页编辑状态 | 使用附着于稳定 `field:<key>` 的局部 `FieldSession` |
| 编辑一个字段会改变其他字段的展示路径 | 所有字段只走唯一 projection + display 管线 |
| 短窗口名册容量包含了列标题行 | `WorkspaceLayout.roster_capacity()` 统一给渲染和翻页使用 |
| 基础菜单的命令执行可能绕过正式入口认证 | 唯一命令入口收敛到 `entry.main` |
| 学生新增和 CSV 导入未完成初始账号交付 | 注册服务原子创建档案与账号；各入口展示成功记录的初始密码 |
| CSV 自行访问数据库、重复关联校验 | CSV 只负责解析与输出，由服务处理注册和校验 |
| 首次改密可继续使用原始密码 | 拒绝与当前密码相同的新密码 |
| 学号可包含非数字，与账号规则存在冲突 | 使用统一数字字符串契约，同时排除 `Administrator` 等非数字账号名 |
| 只读档案焦点被关联链接吸住，无法继续阅读尾部 | 滚动与可见动作选择分离 |
| 切换族系后残留不属于新族系的支系 | 清空不兼容支系，要求重新选择 |
| 删除班级的影响不够明确 | 确认页说明学生将变为未分班，以及被删除的公告数量 |
| 名册仅用颜色表现当前记录 | 增加强、弱记录标记，区分焦点和当前上下文；删除后的空槽明确表示“当前无记录” |

## 架构边界

`schema` 定义字段及校验；`service` 处理业务规则与关联；`repository` 处理业务数据 SQL；`auth` 负责账号与会话。CLI、基础菜单和 TUI 共享这些规则。

工作台中，`state` 只保存明确状态；`student_inspector` 与 `detail` 只定义内容；`inspector` 统一最终几何、绘制、命中与方向导航；`roster` 使用共享布局容量；`field_session` 处理已有记录的局部字段交互；`forms` 只处理完整事务；`events` 分发统一交互意图；`view` 编排布局。

## 验证与边界

核心交互重构使用完整 `unittest` 回归验证，覆盖全部工作台、字段修改、Tab 焦点循环、工具栏命令、取消、关联返回、宽窄窗口、只读权限、账号交付、公告范围和 CSV 部分失败。测试使用临时数据库与认证目录。

Linux 伪终端测试覆盖真实按键解码和终端恢复；POSIX 的 Shift+Tab 序列 `ESC [ Z` 现在按未绑定输入处理。Windows 不再为 Shift+Tab 建立工作台动作映射。PageUp / PageDown、方向键和普通 Tab 继续由物理输入层统一解码。

公告正文可保存多行并换行阅读，但 TUI 当前使用单行输入器；复杂多段正文可通过 CLI 的 `--body` 参数传入。

当前项目没有已发布数据库版本兼容承诺。历史版本缺列的数据库仍遵循项目既有策略：显式重建或另外实施迁移，不能将初始化当作隐式迁移。
